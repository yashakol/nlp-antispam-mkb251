# NLP-антиспам V4 - МКБ251

Публичный код учебного проекта МКБ251: CLI, FastAPI/Uvicorn API и безопасные агрегированные результаты V1-V4. Веса модели в репозиторий не включены. Модель и порог заморожены. Во время упаковки обучение и оценка на 1600 письмах задания не повторялись.


## Получение модели до запуска

Публикация весов отдельно не разрешалась. Для команд `info`, `predict`, `evaluate`, API, smoke-test и Docker требуется файл `models/v4.joblib` из частного проекта, переданного автору отдельно. Публичного URL модели или GitHub Release с весами нет. Поместите доверенный файл по этому пути; SHA256 и порог проверяются по `models/manifest.json`. Не отключайте эти проверки.

Код `research/train_reference.py` показывает один fit на отдельно подготовленных train/calibration JSONL. Он записывает отдельный артефакт, не заменяет V4. Новое обучение не является получением тех же замороженных весов автоматически; для него нужны собственная фиксация данных, новый manifest и проверка calibration. Корпуса и автоматическая подготовка исходных архивов в репозиторий не включены.

## Что проверено

- Загрузка модели, ее SHA256, обе TF-IDF-ветви и фиксированный порог.
- CLI `info`, `predict`, `evaluate`, в том числе запуск из другого рабочего каталога.
- Одинаковый результат для синтетического EML и соответствующих декодированных Subject/body.
- Оценка синтетических данных в JSONL и в каталогах `ham/`, `spam/`.
- Реальный локальный FastAPI/Uvicorn HTTP smoke: GET /health 200, POST /predict 200, неверный payload 400; проверены текстовый и EML-base64 запросы.

FastAPI 0.128.8 и Uvicorn 0.39.0 установлены из PyPI в отдельное окружение проекта. Модель не переобучалась, глобальный Python не менялся. Локальный сервер при проверке слушал только 127.0.0.1 и был штатно завершен после синтетических запросов.

**Docker не проверялся:** Docker CLI найден, но доступ к сокету Docker daemon отклонен средой. Сборка и запуск не выполнялись, права и системная безопасность не изменялись. Dockerfile подготовлен.

## Свидетельство запуска и время ответа

Реальный текстовый вывод: `results/smoke_terminal.txt`; структурированные данные: `results/smoke_test.json`. Скриншот терминала не создавался и не имитировался.

- Загрузка модели после импортов: 191,013 мс.
- Теплый inference одного короткого синтетического сообщения: медиана 1,398 мс, p95 1,550 мс.
- Локальный HTTP round-trip: медиана 2,017 мс, p95 2,203 мс.

По 5 прогревочных и 30 последовательных измерений, batch=1. HTTP включает клиента, сервер, JSON и новое локальное соединение для каждого запроса. Это smoke-замер на одном Mac arm64, не production benchmark и не оценка качества модели.

## Окружение

Фактически проверено: Python 3.9.6, NumPy 1.26.4, SciPy 1.13.1, scikit-learn 1.6.1, joblib 1.4.2, threadpoolctl 3.5.0, FastAPI 0.128.8, Uvicorn 0.39.0. Все установленные runtime-зависимости зафиксированы в `requirements.txt`; полный список также в `results/environment.json`.

Если окружение с этими пакетами уже есть, активируйте его и перейдите в каталог проекта. Команды CLI ниже проверены в таком окружении. В команде `python` должен использоваться именно его интерпретатор.

Для другого компьютера возможная установка в отдельное окружение:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Эта установка с Python 3.11 приведена как инструкция и здесь не выполнялась. Dockerfile также использует Python 3.11. Работа на новой версии Python или платформе требует собственного smoke-test; не используйте автоматически системный Python 3.15 с этими старыми фиксированными пакетами.

## CLI: проверенные сценарии

```bash
python antispam.py info
python antispam.py predict --subject "Project meeting" --body "Please review the agenda for tomorrow."
python antispam.py evaluate --jsonl examples/synthetic_messages.jsonl
python -m unittest discover -s tests -v
```

Модель ищется относительно файлов проекта, а не текущего рабочего каталога. Команда `info` проверяет модель и неизменность парсера по SHA256.

Для одного EML:

```bash
python antispam.py predict --eml /path/to/message.eml
```

Маршрут EML проверен на синтетическом письме. Реальные письма в поставку не входят. Размер одного письма ограничен 2 МБ.

Для уже декодированного UTF-8 тела:

```bash
python antispam.py predict --subject "Example" --body-file /path/to/body.txt
```

Укажите `--html`, если переданное тело является HTML. Не совмещайте `--eml` с `--subject`, `--body`, `--body-file` или `--html`: EML разбирается как MIME, а готовый текст повторно как MIME не интерпретируется.

Ответ - JSON с `label` (`ham`/`spam`), `predicted_label` (0/1), `score`, `threshold` и версией. **Score LinearSVC не является вероятностью.** Правило: spam, если score >= **0.17315834063189364**.

## Оценка своих размеченных данных

JSONL: одна запись на строку:

```json
{"subject":"Example","body":"Decoded text","label":0}
```

`label`: 0 для ham, 1 для spam. Необязательный `html` - boolean. Поля с исходным классом и именем файла не подаются в модель.

```bash
python antispam.py evaluate --jsonl /path/to/labeled.jsonl --output my-metrics.json
```

Или каталог с `ham/*.eml` и `spam/*.eml`, допускаются вложенные подкаталоги:

```bash
python antispam.py evaluate --data-dir /path/to/labeled_mail --output my-metrics.json
```

Оба формата и создание JSON-отчета проверены на синтетических данных. Существующий выходной файл не перезаписывается. Отчет содержит confusion matrix в порядке `[[TN,FP],[FN,TP]]`, accuracy, precision, recall, F1 и FPR. Сами письма и построчные прогнозы команда в отчет не сохраняет.

Независимость оценки определяется происхождением ваших данных. Команда не делает повторно использованный набор независимым. Два письма в `examples/` - только проверка работоспособности, не измерение качества.

## Локальный HTTP API: FastAPI + Uvicorn

На компьютере, разрешающем локальные сокеты:

```bash
python antispam.py serve --host 127.0.0.1 --port 8000
```

В другом терминале:

```bash
curl --fail --silent http://127.0.0.1:8000/health
curl --fail --silent http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  --data-binary @examples/request.json
```

`GET /health` возвращает версию, хеш модели и порог. `POST /predict` принимает:

- `{"subject":"...","body":"...","html":false}`; или
- `{"eml_base64":"..."}` как единственное поле для EML, закодированного base64.

Неверный payload возвращает 400, неверный Content-Type - 415. Ограничение HTTP-запроса - 2,8 МБ; EML после base64 - 2 МБ. API не принимает пути к локальным файлам, не сохраняет письма и не ведет журнал текстов запросов. По умолчанию слушает только localhost.

Опциональный сетевой тест:

```bash
NLP_HTTP_SMOKE=1 python -m unittest discover -s tests -v
```

Обычная команда unittest пропускает сетевой тест и проверяет остальные сценарии. Реальный сетевой smoke при упаковке выполнен через `smoke_check.py` с отдельным новым каталогом свидетельств: `python smoke_check.py --output-dir NEW_EVIDENCE_DIRECTORY`. Он использует только синтетическое сообщение, не обучает модель и не читает реальные корпуса.

## Docker: только подготовленные файлы, сборка не проверена

Эти команды **не выполнялись**:

```bash
docker build -t nlp-antispam-v4 .
docker run --rm -p 127.0.0.1:8000:8000 nlp-antispam-v4
```

Контейнер запускает тот же локальный API, без повторного обучения. Dockerfile и `.dockerignore` включают только runtime, зависимости и выбранную модель. Здесь не заявляется проверенная сборка, работоспособность контейнера или публичное развертывание.

## Результат и ограничения

На известных 1600 письмах задания (600 ham, 1000 spam):

| Версия | Accuracy | FP | FN |
|---|---:|---:|---:|
| V1 | 80,7500% | 264 | 44 |
| V2 | 88,5625% | 121 | 62 |
| V4 | 92,8750% | 22 | 92 |

V3 на этом наборе не оценивалась. V4 дает на 99 ложных тревог меньше, чем V2, но пропускает на 30 spam больше. Precision V4 97,6344%, recall 90,8%, F1 94,0933%, FPR 3,6667%.

Эта заключительная оценка V4 выполнена на уже известном наборе, не blind test. Для итогового программного пакета пользователь выбрал V4; это не утверждение безусловного превосходства над V2.

На новом SpamAssassin holdout FP снизились с 248 до 33, FN с 20 до 18. Но там только 119 spam: сохранение recall в пределах 1 п.п. не подтверждено парным интервалом. На прежнем holdout из трех источников FP снизились с 44 до 42, а FN выросли с 62 до 91. Полные цифры и разделение разных проверок приведены в `RESULTS_RU.txt` и `results/metrics_v1_v4.json`.

Обучение ориентировано на исторические преимущественно англоязычные источники. Перенос на современную русскую почту не доказан. Near-дедупликация эвристическая; отсутствие всех общих кампаний не гарантировано. Встречаются неоднозначные кодировки, остаточные spam-маркеры в Subject и похожие на заголовки строки внутри тела. Они не изменялись после фиксации модели.

## Состав и воспроизводимость

- `antispam.py`, `api.py`, `service.py` - CLI и локальный FastAPI/Uvicorn API.
- `smoke_check.py` - синтетическая проверка запуска и локальные замеры времени.
- `maildata.py` - неизменный парсер/нормализатор V2/V4.
- `experiment_common.py` - неизменные TF-IDF, scoring и правила выбора порога.
- `models/manifest.json` - параметры и SHA256 выбранной модели. `models/v4.joblib` отсутствует в публичном репозитории.
- `results/` - агрегированные метрики, хронология и реальный статус проверки поставки.
- `PROVENANCE.json` - источники, атрибуция, хеши и размеры разбиений.
- `research/protocol_v4.json` - протокол. Построчные IDs и данные в публичный репозиторий не включены.
- `research/train_reference.py` - переносимый код одного fit для отдельно подготовленных train/calibration JSONL; при упаковке не запускался.
- `examples/`, `tests/` - явно синтетические примеры и smoke-tests.
- Частный пользовательский ZIP дополнительно содержит веса, IDs и контрольные суммы.

Исторические нормализованные train/calibration должны быть подготовлены отдельно; исходные корпуса, извлечение всех данных и near-группировка автоматически этой поставкой не воспроизводятся. `train_reference.py` требует JSONL с `text`, `label`, `source_id`, `group`, ровно 28493/7555 строками и новым выходным каталогом. Он не меняет поставляемую модель, не открывает holdout и не делает refit на calibration.

Модель joblib предназначена для загрузки из этой доверенной поставки. Ее SHA256:

`8baa5c13493897b6138e814b942860a0de4c75f78b15fabedf6f19bf95739813`

Корпуса, реальные письма, персональные данные, секреты, внутренние рецензии и промежуточные модели в пакет не включены. Извлечения текстов из словаря TF-IDF и весов отдельно не публикуются.
